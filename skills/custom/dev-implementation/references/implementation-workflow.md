# 实现执行规则

Dev Agent 的任务是执行已确认方案，而不是重新定义需求或技术方向。

## 输入优先级

| 来源 | 用途 |
| --- | --- |
| `product-specs/.../prd.md` | 判断需求范围和验收标准 |
| `tech-specs/.../tech-design.md` | 判断设计方案、接口/数据/兼容性 |
| `tech-specs/.../implementation-plan.md` | 拆解开发步骤 |
| `tech-specs/.../test-plan.md` | 决定测试覆盖和命令 |
| `tech-specs/.../risk-checklist.md` | 判断禁止项、审批项和高风险项 |
| `llm-wiki/` | 保持业务语义正确 |
| 代码和测试 | 最终实现事实来源 |

## 可继续实现的条件

- PRD 有明确目标和验收标准。
- 技术方案没有标明阻塞。
- 风险清单没有未审批高风险项。
- 实现计划给出了足够的文件范围或可通过代码定位。
- 测试计划至少说明了核心验证方式。

不满足时，输出阻塞说明，不要强行实现。

## 修改原则

- 小步修改，小步验证。
- 优先复用现有模块接口和测试模式。
- 修改只围绕当前 `spec_id`。
- 保持 PRD 的非目标范围。
- 不做无关格式化、重命名或重构。
- 不碰与技术方案无关的文件。

## 测试失败处理

测试失败时不要掩盖。记录：

- 命令
- 退出码
- 关键错误
- 是否与本次改动相关
- 已尝试修复
- 下一步建议

如果失败来自环境缺失或外部服务不可用，说明证据；如果失败来自本次改动，应优先修复。

## 实现报告中的偏差分类

| 分类 | 处理 |
| --- | --- |
| 文件路径偏差 | 记录实际文件路径和原因 |
| 轻微实现细节偏差 | 可继续，记录原因 |
| 接口/数据契约偏差 | 停止并请求确认 |
| 权限/安全偏差 | 停止并请求确认 |
| 需求范围偏差 | 停止并请求确认 |
| 测试策略偏差 | 记录并说明替代验证方式 |

## PR/MR 前检查

- `implementation-report.md` 已更新。
- `test-result.md` 已更新。
- `pr-description.md` 已生成。
- 工作区没有无关改动。
- 高风险项没有被静默修改。
- PR/MR 描述包含 AI 生成或 AI 辅助标识。
